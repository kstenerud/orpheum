## What M5 asks

cut-a's M5 row (D245):

- **Deliverable:** one skinned web UI, from research into best practice, competitors and what people
  say of them, and into what the web's practice forgot of older UI toolkits; a UI principles
  document, with the standards that touch the UI revisited against it; an architecture supple enough
  to iterate on.
- **Acceptance:** the two people use it in their web browsers, the remote one's voice on her phone's
  browser, and the owner calls it polished. A change to one screen's look needs no change elsewhere.

## How M5 is worked (the owner, 2026-10-09)

- **UX flow and ease of use are the primary driver** of the UI design, held to a set of principles
  drawn from the work and writings of the field's leading practitioners:
  [ux-principles-2026-10-09.md](../research/ux-principles-2026-10-09.md).
- **The UI will take a lot of iteration, so the loop must be quick.** The owner asks for a change,
  it is made, and staging shows it at once. Commits and gates come only once the owner is happy
  with the change. How staging does this is open (below).
- **An inventory of everything planned or designed outside M5** comes first, so the owner can
  check the feature list and the UI can leave room for every item:
  [feature-inventory-2026-10-09.md](../research/feature-inventory-2026-10-09.md).

## Questions for the owner, before the first line

From [ui-architecture-2026-10-05.md](../research/ui-architecture-2026-10-05.md) §6:

1. **Is D138 §4's user-facing theming seam still wanted,** now that D245 asks for one skin? If yes,
   class names and tokens are a public surface and stay stable. If no, scoped class names become an
   option and the tokens can change freely. *The owner, 2026-10-09: unsure; in his experience
   themes rarely keep up with the app, and he ends up on the default. Researched in
   [theming-2026-10-09.md](../research/theming-2026-10-09.md). Decided by D271 §2–3: no
   user-facing theming, and no light palette.*
2. **stylelint, or a Python check,** to enforce the CSS rules? stylelint is a new dependency
   (rule 3); the check is a change to `scripts/` (rule 2). *The owner, 2026-10-09: an external
   tool is fine where it does the job well enough.*
3. **Which browsers are the floor?** It decides container queries, popover and `@scope`, and the
   Media Session that D268 §4 relies on, and depends on what the Cast receiver and the laptops run.
   *The owner, 2026-10-09: research what media-server users consider important, from competitors'
   support requests among other things. Without a clear picture: Chrome, Safari, Edge and Firefox,
   with version floors chosen by the bugs fixed in each, and no more unless there is a compelling
   reason, as each adds to the test cycle. Researched in
   [browser-support-2026-10-09.md](../research/browser-support-2026-10-09.md). Decided by D271
   §1: Chrome and Edge 120, Firefox 140, Safari 17.1.*
4. **A behaviour library:** none for now, and which one when the first hard widget comes?
5. **Keyboard arrow navigation** in grids and rows: in Cut A, or with the television milestone?
   *Answered 2026-10-09: from the start, in M5.*
6. **A specimen screen in the app, or Storybook or Ladle?**
