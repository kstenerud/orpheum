# Testing strategy

- **Depends on:** —


**Fixtures never contain commercial content** ([D187](../../decisions/working-notes.md)). Media in the corpus is generated,
public-domain or Creative Commons (Blender's open films, the Internet Archive's public-domain
collection); filename-parser cases exercise real naming *patterns* with synthetic titles. youtube-dl's
2020 takedown cited test cases naming label videos.
## Why it needs its own plan

Most of this product's correctness lives where a normal unit test cannot reach: real media,
real hardware encoders, real client decoders, real filesystems. The incumbents' trackers are
full of bugs only a corpus could have caught — HDR tone-mapping regressions, "works for four
minutes then errors", NVENC ignoring `-force_key_frames`, captions destroyed by a transcode,
subtitle desync on resume.

And the project's premise is that strong typing plus strong linting help agents write quality
software. They catch a class of error; **none of the above is in that class.** The gate has to
be tests.

## The corpus: five tiers, four of them in the repository

[D109](../../decisions/working-notes.md). The original question — *"how does a contributor
without 200 GB of media run the suite?"* — had a false premise. Nobody's corpus is 200 GB:
Jellyfin's test suite contains **no media files at all**, Navidrome's contains **13 files and
512 KB**, and FFmpeg's — the codec library underneath everything — is **1.29 GiB with a median
file of 58.7 KB**.

| Tier | What | Cost | Asserts |
| --- | --- | --- | --- |
| **0** | no fixtures; table-driven pure functions | none | parsing, track-kind derivation, language normalisation, predicate compilation, sort keys, pseudonymisation |
| **1** | **recorded node reports and probe JSON** | kilobytes | the whole core interpretation layer |
| **2** | clips generated by the test run | **8.9 s, 5.9 MB** | node pipeline, stream service, remux, subtitle extraction |
| **3** | a small real set, in-tree, chosen for pathology | ~1 MB | the boundary: junk files, corrupt frames, lying extensions |
| **4** | external, opt-in, **announced when skipped** | rsync | codec diversity, if it is ever needed |
| **5** | hardware | [device-lab.md](device-lab.md) | clients, decoders, encoders |

**Tier 1 is the main event, and [D59](../../decisions/working-notes.md) is why.** Jellyfin
tests its media layer with fifteen recorded `ffprobe` outputs totalling 120 KB — for them, an
internal detail pressed into service. For us probe output is a **wire format**: the node
reports it, the core interprets it. So filename parsing, grouping into four levels, track-kind
derivation, segment placement, certification mapping and identification all replay from
recorded JSON with **no FFmpeg, no filesystem and no media**. That is the property D59 was
argued for, arriving in the test suite.

**Tier 2 is generated, not committed.** 16 clips across eight codec/container combinations at
two resolutions cost 8.9 seconds and 5.9 MB to produce. The generator goes in the repository;
the clips do not, because the generator is the readable specification of what each clip is.

**Tier 3's files are named after bugs.** Navidrome's are the model — `._02 Invisible.mp3` is
an AppleDouble sidecar a scanner must skip; `test-invalid-frame.mp3` is deliberately corrupt;
`no_replaygain.mp3` sits beside `zero_replaygain.mp3` to separate *absent* from *zero*. Ours,
to start: an AppleDouble file, a truncated container, a `.mkv` that is not Matroska,
`ger`/`deu` disagreeing within one file, a file with no runtime, an ASS with an embedded font,
a 5.1 track with no loudness metadata. A file earns its place by reproducing a failure, never
by covering a codec — that is what tier 4 is for.

**Tier 4 copies FATE's mechanism, and the part to copy is the announcement.** Without
`SAMPLES=` set, FFmpeg's build prints *"warning: only a subset of the fate tests will be run"*
and runs the generated subset. A degraded test run that says so is worth more than the rsync.

**So `go test ./...` on a clean checkout needs no download, no FFmpeg and no media.**

## What each assertion may be

[D110](../../decisions/working-notes.md). The assertion is chosen per test from a closed set,
and the loosest is never the default. FATE's set is the model: exact `diff` for text;
`framecrc`/`framemd5` where output genuinely is bit-exact; a threshold comparison only where
it is not; purpose-built comparators (`tiny_psnr`, `tiny_ssim`) rather than a general one; and
a per-test tolerance rather than a global one.

**Every threshold gate compares against a frozen baseline, never the previous run.** Borrowed
from VMAF practice, where the just-noticeable difference is ~6 points: a sequence of
96.0 → 95.6 → 95.2 → 94.8 → 94.4 → 94.0 passes every build-to-build tolerance and has lost two
points in six builds. This is not a video rule — it governs the latency gates in
[performance-targets.md](performance-targets.md) identically, and re-basing a baseline is an
explicit reviewed act, not a flag somebody runs to make CI green.

**Quality gates run on seconds of video.** Measured: VMAF on a 10-minute 1080p file with six
threads takes **344 s, 1.7× realtime** — the most expensive operation measured anywhere in
this project. Conversely a remux with no re-encode is **2,163× realtime**, so the conformance
tests that matter most ([D86](../../decisions/working-notes.md)'s segment grid and IDR
alignment) are free on every commit.

## `assumptions/`

[D111](../../decisions/working-notes.md), stolen from shaka-player. A test directory whose
only job is to pin the things we do not control and whose violation would be **silent**: Go's
ASCII-only regex classes, `x/text/collate`'s pinned CLDR version, FTS5 tokeniser immutability,
SQLite's 1000-term and 65-table limits, `ass_track_set_feature`'s −1 return, FFmpeg's default
`drc_scale`, chromaprint's refusal of a 5.1 input, NVENC's `-force_key_frames`,
`SQLITE_BUSY_SNAPSHOT`'s unretryability, and the WAL file-copy trap.

One from [D129](../../decisions/working-notes.md): **a client that advertises no `zstd` still
gets a working response**, gzipped rather than refused — the failure mode being a television
that silently receives bytes it cannot decode.

One from the trash design ([D145](../../decisions/working-notes.md)): **the path-length
ceiling**, because nesting a library-relative path under an event directory adds ~40
characters — nothing against Linux's 4096 and possibly something against a legacy
260-character limit over SMB. (A `link(2)` probe was going to live here too, until
[D146](../../decisions/working-notes.md) removed the dependency: the retained files are
kilobyte sidecars, so they are copied, and exFAT's lack of hardlinks stops mattering.)

Two more from the 2026-09-21 transport round
([D127](../../decisions/working-notes.md)), and both are the silent kind: **`nfs(5)`'s
attribute-cache defaults** (`acregmax`/`acdirmax` 60 s, doubling towards the maximum), because
a change there quietly re-times every claim about the file channel; and **SMB's rename
semantics**, since some server/client combinations reject a rename onto an existing target or
do not make it atomic. We rename onto a new name, which mostly avoids it — "mostly" is what an
assumption test is for.

Each is one small test. Together they are the difference between "a dependency upgrade changed
something" and "a dependency upgrade broke Thai line-breaking and a user told us".

## The gates

- **The confinement is probed and asserted, not assumed** ([D112](../../decisions/working-notes.md)).
  Measured in a stock Linux 6.17 container: `landlock_create_ruleset` returns `ENOTSUP` while
  seccomp is active. Docker is how most people will run this. So the node probes at startup,
  reports what it actually got, the core can say "this node is running FFmpeg unconfined", and
  the escape test attempts the forbidden open and asserts the denial — skipping **loudly**
  where the mechanism is absent.
- **A breaking change to the generated OpenAPI document fails the build**
  ([D85](../../decisions/working-notes.md)), diffed against the last release, waivable only in
  the changelog. This is the thing that would have caught Jellyfin 12.0 removing `/emby/`
  before its users did.
- **Apple's `mediastreamvalidator` and `hlsreport`** against our own HLS output — they check
  the specification and the *authoring* specification respectively, and Apple's guidance is to
  run both. **macOS-only**, so this is a release gate on a Mac, not a per-commit step.
- **An IPv6-only run.** Jellyfin has two open issues from single-stack installs. One matrix row.
- **Conformance tests ship as part of the plugin contract**
  ([D19](../../decisions/working-notes.md), [D23](../../decisions/working-notes.md)): a
  transcoder claiming a profile must produce it, and must carry closed captions through.
- **A skip list keyed by platform**, in the hls.js shape (`skip_ua` per stream). A structured
  record of known-broken combinations beats a commented-out test, and it is where
  [D92](../../decisions/working-notes.md)'s failure reports land.

## Two assertions from the gap sweep

[D140](../../decisions/working-notes.md):

- **A library with `.nfo` sidecars imports their contents as user overrides on first scan**,
  and a subsequent metadata refresh does not overwrite them
  ([D7](../../decisions/working-notes.md)). This is the migration case, and the failure is
  silent — a user whose corrections vanished will not file a bug, they will leave. Tier 3
  gains a fixture: a film with a Kodi-dialect `.nfo` whose title disagrees with both the
  filename and the provider.
- **A watchlist entry survives a rescan, a rename and a provider change**, like every other
  piece of user-authored state.
- **The NFO round trip** ([D141](../../decisions/working-notes.md)), which is the only test
  that proves the portability promise the README makes: import a Kodi library, correct
  something, export, and **Kodi reads the correction back and does not re-scrape over it** —
  i.e. `lockdata`/`lockedfields` were written, not just the value. And a sidecar containing
  elements we do not model survives read-edit-write **byte-comparably in those elements**, so
  a round trip through our server never deletes what another tool wrote.
- **No per-user state reaches a sidecar** ([D98](../../decisions/working-notes.md),
  [D141](../../decisions/working-notes.md)) — no `playcount`, no `lastplayed`, no `watched`,
  by default and on any code path. The media tree is shared, so this one fails closed. It
  appears **only** when an export explicitly named one user
  ([D142](../../decisions/working-notes.md)), and then only that user's;
- **no code path removes a file beneath a media root** ([D144](../../decisions/working-notes.md)).
  Deletion is deferred and the policy is an *enforced absence*, so this is the assertion that
  keeps it true — cheaper to maintain than the feature was to build, and it is
  [D89](../../decisions/working-notes.md)'s actual purpose preserved: *"unstated, this ends
  with `os.Remove` in a handler"*;
- **a sidecar write is atomic and keeps what it replaced** — a crash mid-write leaves the
  original intact, and overwriting an existing `.nfo` retains the previous version
  ([D144](../../decisions/working-notes.md)). We can destroy user data by *writing*, so this
  gate does not wait for deletion;
- **an entire export is restorable with `cp -a` and nothing of ours**
  ([D145](../../decisions/working-notes.md)) — the event directory mirrors the library's
  structure, so the test copies it back with a shell command and asserts the tree matches
  what was there before. This is the *survive-us* property, and a test that used our own
  restore code would not prove it;
- **an unchanged sidecar is neither rewritten nor retained** — exporting twice over an
  unchanged library produces **one** event directory, not two
  ([D145](../../decisions/working-notes.md)). Without this the trash grows by thousands of
  identical files per export;
- **our own restore trashes the current file first**, as a new event, so restoring an older
  version never destroys a newer one ([D145](../../decisions/working-notes.md));
- **the export's default follows the account count** — one user preselects that user, two or
  more preselects none ([D143](../../decisions/working-notes.md));
- **an export stops a scan running on the same root**, and the scan resumes rather than
  restarts ([D143](../../decisions/working-notes.md), [D102](../../decisions/working-notes.md));
- **an export onto a read-only root reports rather than fails**, per root and per item, and a
  library spanning a writable disk and a read-only mount exports the half it can
  ([D142](../../decisions/working-notes.md)) — stopping at file 1,400 of 3,500 with one
  boolean is the behaviour to fail;
- **a node's own sidecar writes do not produce a scan storm.** The node reports them, because
  [principles §9](../../principles/README.md) forbids a sensor suppressing its own output;
  **the core ignores what it commanded** ([D142](../../decisions/working-notes.md)). The
  regression this catches looks exactly like "the scanner went mad after I exported";

## The subtitle-verification assertions

[D147](../../decisions/working-notes.md), [D148](../../decisions/working-notes.md). These are
the ones that keep a headline claim honest, and the first is the one that matters most:

- **An unverified subtitle track is never presented as a verified one.** Every surface that
  offers a track — the picker, the fetch result, the API — distinguishes *scored above
  threshold*, *scored below*, and *never scored*. This fails closed: the default for a track
  with no measurement is "not verified", not "presumably fine". Without this the feature is
  the button everyone already dislikes, with extra machinery behind it.
- **A deliberately desynced subtitle is corrected to within the same tolerance as one that was
  never desynced.** Tier 3 gains a fixture film with a correct cue set and derived copies
  carrying a constant offset, a 25/23.976 ratio, and both. This is a property test, not a
  golden value: *corruption must not degrade the result*, which is the measured behaviour
  (0.130 s worst-cue on Tears of Steel, identical across every injected corruption) and the
  thing that makes ranking-after-correction valid.
- **A subtitle for the wrong film is rejected.** The negative control is a second film's
  subtitles against the first film's speech map. Measured separation was 3.4–3.6×; the gate
  is that nothing from the wrong film clears the acceptance threshold.
- **A user-set offset survives re-verification and outranks the computed one.** A human who
  nudged and kept watching is ground truth, and the regression this catches is a background
  re-score silently undoing it.
- **The parser survives the real corpus.** Fixtures taken from actual releases: a `.srt` that
  is an HTML page, `- >` in place of `-->`, cue text on the timestamp line, UTF-16 with a BOM,
  and a legacy single-byte encoding. **7 of 65 files in two *official* distributions needed
  tolerant parsing**, so this is the ordinary case, not the adversarial one — and a strict
  parser's zero-cue result reaches the user as "the download failed"
  ([threat-model.md](threat-model.md)).
- **The speech map is derived, and a rebuild reproduces it.** Deleting it and rescanning
  yields the same map and the same scores; a restore that omits it loses nothing
  ([backup-restore.md](backup-restore.md)).

And one for `assumptions/`, of the silent kind: **the VAD's output is pinned**. The detector is
a third-party model, a model upgrade changes every score in the library, and the failure is
invisible — subtitles quietly stop verifying, or quietly start. One short clip with a known
speech fraction, asserted.

## Assertions from the 2026-09-21 source sweep

[D149](../../decisions/working-notes.md), [D150](../../decisions/working-notes.md).

- **No code path accepts a PIN as an authentication factor.** Fails closed, and it is the
  exact bug Jellyfin shipped and then removed for being *"a big security risk especially for
  administrator accounts"*. A PIN may only gate a profile switch on a session that is already
  authenticated ([threat-model.md](threat-model.md)).
- **A stream is refused, with a reason, when the role's bitrate or concurrent-stream ceiling
  is reached** — and the refusal is distinguishable from a failure
  ([D92](../../decisions/working-notes.md), [auth.md](auth.md)). The regression this catches
  is a relay bill.
- **An external-score predicate does not silently match unrated items.**
  `imdb_score < 6` over a Title with no score must behave like
  [rules-engine.md](rules-engine.md)'s existing null rule for play count, and the test is the
  never-scored item.
- **A statistics page shows a user only their own history unless the role grants otherwise**
  ([play-statistics.md](play-statistics.md)).
- **No endpoint accepts a credential from a URL** ([D154](../../decisions/working-notes.md)).
  Mechanical and route-by-route: no query parameter and no path segment is ever read as a
  token. This is the single assertion that keeps *"Copy Stream URL leaks the session key"*
  from happening here, and it fails closed.
- **No grant is stored in plaintext**, and no secret reaches a log, a metric label or a bug
  report ([bug-reports.md](bug-reports.md)) — the last one matters because a URL in a report
  is how a credential escapes a system that was otherwise careful.
- **Every grant kind has a scope**, asserted over the enum, so adding a kind without one
  fails the suite rather than shipping Jellyfin's unscoped `ApiKey`.
- **A revoked grant stops working on the next request**, including mid-stream — revocation is
  the control ([D117](../../decisions/working-notes.md)), so latency here is the property.
- **The media cookie cannot reach the API**, and the API refuses a cookie outright. The two
  paths are separate or CSRF becomes real ([D154](../../decisions/working-notes.md)).
- **The last administrator cannot be removed or demoted** ([D154](../../decisions/working-notes.md)).
- **A Version with no Edition is a first-class row, not a synthetic one**
  ([D155](../../decisions/working-notes.md)), and **naming its Edition later moves no state at
  all** ([D157](../../decisions/working-notes.md)). The fixture is the owner's own case: four
  unidentified cuts of one film, each watched to a different point, then labelled — including
  labelling two of them as the *same* Edition. Every position must be byte-identical
  afterwards.
- **Only a File holds a playback position** ([D157](../../decisions/working-notes.md)),
  asserted structurally: no Title, Edition or Version row has a position column. This is
  [principles §13](../../principles/README.md)'s gate, and it is the one that failed twice
  before it was written.
- **Completion rolls up and a position does not.** Finishing one Version marks the Edition and
  Title watched; it must not seed a position anywhere
  ([D157](../../decisions/working-notes.md)).
- **A multi-part resume returns to the right part.** `12:30 into part 2` survives a restart,
  and the whole-film progress shown in the UI is derived on read rather than stored.
- **Switching a series' ordering moves no stored state** ([D159](../../decisions/working-notes.md)):
  every position is byte-identical afterwards and only Next Up changes.
- **A user-authored ordering survives a full rescan and a provider refresh**, name included
  ([D159](../../decisions/working-notes.md)).
- **A multi-episode file holds one position**, and per-episode completion is derived from the
  `episode_boundary` segment rather than stored — so a wrong boundary misreports completion
  and loses no position ([D159](../../decisions/working-notes.md)).
- **An explicit Collection's order is preserved and may omit members** — the fixture is the
  Machete order, IV V II III VI with Episode I absent
  ([D159](../../decisions/working-notes.md)).
- **Next Up works over a Collection whose members are films**, and over one whose members are
  **other Collections** ([D160](../../decisions/working-notes.md)). Fixtures: a franchise run,
  and *Gruelstone → Lockfast*, where finishing the last episode of the first series must
  yield the first episode of the second.
- **A nested Collection uses the viewer's own ordering preference for the inner series**
  ([D24](../../decisions/working-notes.md), [D159](../../decisions/working-notes.md)) — the
  composition must not flatten to a provider default.
- **A predicate Collection's sequence is a sort, and a newly-added member appears in it**
  without anyone editing a list ([D160](../../decisions/working-notes.md)).
- **A Collection cannot contain itself**, directly or transitively; the write is refused
  ([D160](../../decisions/working-notes.md)).
- **No surface offers a position from one file against another**
  ([D158](../../decisions/working-notes.md)). A negative assertion, because a withdrawn
  feature with no test is a feature somebody re-adds — and this one was re-added once already
  within a day of being removed.
- **A file whose content hash changed starts at zero**, and the previous position is not
  carried onto it ([D116](../../decisions/working-notes.md),
  [D158](../../decisions/working-notes.md)). Fixture: the owner's re-rip, and a hand-edited
  cut.
- **A user-created Edition survives a full rescan and a metadata refresh**, name included
  ([D141](../../decisions/working-notes.md), [D158](../../decisions/working-notes.md)).
- **A client names the failing hop** ([D152](../../decisions/working-notes.md)). Four
  fixtures — no network, relay unreachable, relay up with the core not dialled in, core up
  with the media node asleep — and four distinguishable messages. *"Cannot connect"* for any
  of them is the failure, because it is the message that generates the support request.
- **The relay's gap annotation carries counts and a window, never an identity**
  ([D72](../../decisions/working-notes.md), [D152](../../decisions/working-notes.md)). Fails
  closed, and it sits with the other privacy assertions rather than the connectivity ones.

## The two UI gates, which exist to settle an argument

[D138](../../decisions/working-notes.md), [D139](../../decisions/working-notes.md).
**Clicks from home to playing a chosen title**, and **D-pad-press to selection moving**, both
frozen-baseline gates like every other threshold here
([D110](../../decisions/working-notes.md)).

Their purpose is not only speed. Every redesign draws backlash, so its existence proves
nothing, and these two numbers are what **separate "angry at change" from "angry at worse"
automatically, before anyone posts anything**: a layout change that holds both is a change; one
that worsens either is a regression whatever its reception. Without them the argument is
unfalsifiable in both directions — which is how a real regression gets dismissed as novelty,
and how a good change gets reverted.

## Done when

`go test ./...` passes on a clean checkout with no media and no FFmpeg; the tiered suite says
which tiers it skipped and why; a breaking OpenAPI change fails CI; the sandbox escape test
runs on a machine with Landlock and skips loudly on one without; and the `assumptions/`
directory has caught at least one dependency upgrade.
