# Before M4: the whole-checklist audit (2026-10-03)

AGENTS.md rule 17 asks for the whole [checklist](../../audit-checklist.md) at every milestone. This
one covers everything since [the readiness audit](audit-2026-09-30.md) (`"docs(audit): before Phase 4, the design, the architecture, the principles and the gates"..ef7c6d6`, 150
commits): the jobs rebuild's Phases 4–6, the split of `internal/core/playback`, and D242. Five
read-only reviews ran in parallel (design against what was built; naming in Go; naming in the web
client; the architecture map, duplication and derived data; hardcoded values, failure classes and
the documents). The coordinator took the process items and checked the findings that matter most
at their use sites before writing them here.

## 0. The verdict

**The code is sound and M4 is not ready to start.** What was built does what its decisions say,
nearly clause for clause, with tests that exist. The audit found two defects in behaviour, one of
them a regression of mine fixed during the audit (§1), and a backlog of documents that no longer
say what is true, chief among them cut-a §4, the node protocol, which still describes the protocol
from before D234. M4 is blocked on decisions, not code: D223 §11's nine questions, M4's
dependencies, and how backups become jobs (§8).

## 1. Fixed during the audit

- **Restore refused the snapshot kept before a migration**. D242's backup made
  restore take only tarballs of `persistent/`; the migration runner still keeps
  `pre-migrate-vN.sqlite`, a database alone, and the server's refusal of a newer database and
  doctor both name it as the way back (D181). Restore now takes either.

## 2. Defects to fix (no design needed)

1. **The loudness sweep's root rule drifted.** `ListFilesToMeasure` (`store/queries/loudness.sql:19`)
   has its own copy of "under a missing root", without the clause D233 §10 added to
   `ListUnavailableRootsOfNode` (`root_state.sql:81`): a root made unavailable by a disk stall is
   swept anyway, and its measurements park, against loudness `doc.go`'s invariant. Fix: one SQL
   source for the rule, and a test with a stalled root.
2. **A played video's subtitle extraction falls to background while its player still asks.**
   `subtitles.TextOf` answers 425 without `KeepWanted`, which renditions calls (`renditions/files.go:53`);
   after `play_wanted_seconds` a slow extraction is demoted though someone is watching (D234 §3).
   Fix: call it, with a test like `TestPrepare_APlayerAskingForTheRenditionKeepsItsPrepareWanted`.
3. **Parking a job on a missing root is written twice:** `library.ParkIfUnavailable`
   (`playable.go:107`) and `artwork.Service.localFile` (`artwork/service.go:170`). Fix: one.
4. **A doc citation names the wrong test:** `nodes/doc.go:94` cites, for "a command carries its
   job's priority", a test that asserts nothing about priority.
5. **Untested components:** `library.Scans.InProgress`, `jobqueue.endProbeUnanswered`; and two dead
   wrappers, `jobs.Queue.Wake` and `ProbeNow`.
6. **A config key with no bound breaks a promise:** the core's `movementWindow` (30 min,
   `nodes/exchange.go:142`) must outlast the node's read window, `5 min + node.probe_timeout_seconds`,
   which has no maximum. Fix: bound the key below 25 minutes in `NodeConfig.check`.

## 6. The architecture map (item 20)

- **Storage:** ten tables missing (`artwork`, `library`, `device_reader_limit`, `refresh_request`,
  `fetch_failure`, `edition_text`, `group_text`; `scan`, `scan_batch`, `node_attempt`), the

  ("the TMDB client"), `artwork` ("owns the image vocabulary"), `nodeproto` ("JSONL reports").
- **Seams:** new crossings (library → nodes and jobs; artwork, loudness, subtitles, renditions →
  library; providers/tmdb → library; playback → auth); moved line references.
