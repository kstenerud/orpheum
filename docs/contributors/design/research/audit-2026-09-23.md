> **ABOUTME:** The second independent audit, taken before any code: whether the design and
> architecture make sense, what is overbuilt, whether the technology choices still hold in
> 2026, how the software should be packaged and kept simple to run, how to structure a codebase
> that agents write, and whether Cut A is ready to build.

# Audit, 2026-09-23 — before the first line of code

**Method.** Five reviewers worked independently and in parallel, each with a fresh context and
no knowledge of the others:
- architecture and overcomplication
- readiness to build Cut A
- the technology stack against the September 2026 ecosystem
- packaging, installation and maintenance across the field
- how to structure an agent-written codebase, including yoloAI's record

Each claim below that changes a decision was re-checked against the tree or the cited source
before it was written here. The reviewers' working reports and fetched sources stay outside the
repository:
- `/yoloai/cache/research/audit2-{architecture,readiness,tech,packaging,llm}.md`
- `/yoloai/cache/http/audit2*/`

`WN:n` means line *n* of [working-notes.md](../../decisions/working-notes.md) at the time of
writing.

## 0. The verdict

**The ideas are right, the mechanisms are overbuilt, and the build contract is missing.**

- **Several core ideas are better than anything else in the field and should not move:**
  - the client choosing from a closed menu (D2, D21, D22)
  - files as the source of truth, with a payload-anchored identity (D179)
  - the play log with a guarded position (D81, D165)
  - four levels, as `schema.md` actually implements them (cheap: Edition is optional, the
    position is on the File)
  - the migration policy (D181)
  - one metadata source, fetched once (D170)
  - opaque revocable grants (D154)
- **Two earlier cuts kept the schema proportionate, but the machinery was never cut.**
  - D178 cut features and D180 cut the schema.
  - The research rounds of D80–D108 and D140–D152 were each additive: every gap they found got a
    mechanism.
  - Nobody has yet cut mechanisms. That is the third cut, and §2 proposes it.
- **Cut A's hardest component has no home.** Turning an MKV into something a browser and a
  Chromecast will play is assigned to no process and to no mechanism (§1.1).
- **Readiness: ready with conditions.** What to build and why is settled far more thoroughly
  than usual. What is missing is everything a builder reads line by line:
  - no API endpoint list, no wire format for the node report or for Watch Together, and no
    FFmpeg command lines
  - no process topology and no TLS plan
  - no repository layout and no standards
  - no licence files and no code CI
  - about 1–2% of the ~360k words is directly buildable (`schema.md`, `migrations.md`)
- **The conditions are few and cheap** (§8). Phase 0 has still not been run after 190
  decisions, and four afternoons of measurement would settle choices the documents keep
  debating.

**Recommendation: freeze design for Cut A once the conditions are met.** After that, a new
decision is made only when code or a measurement forces it.

## 1. Architecture: findings by consequence

### 1.1 The remux and audio path has no process home — **confirmed**

- **D26 keeps FFmpeg out of the core.** D190 makes that an architecture test.
- **Several documents put the work in the core anyway:**
  - The overview diagram places *"direct-play, remux, AUDIO encode"* in the core's `stream/`
    ([overview.md](../overview.md), the architecture diagram, and *"the core needs no video
    encoder — but it does encode audio"*).
  - [transcoding.md](../plans/transcoding.md) says audio transcoding *"lives in the core"*.
  - D128 says *"the core serves the film, which in the default topology it does"* (WN:8211).
- **[stream-service.md](../plans/stream-service.md) never says which process runs FFmpeg.** It
  lists remuxing and audio encoding as that service's work.

This is the hot path of every Cut A playback, since D178 makes remux mandatory. The first line of
playback code would have to decide it.

**Resolution proposed** (§9, P1): the node does every file read and every FFmpeg run. The core
authenticates and reverse-proxies `/media/*` to the node over its socket. D33 then stays
literally true, and a remote node later is a redirect.

### 1.2 Live segment-addressed remux is the hardest Cut A component, and is treated as free

- **The tree calls it cheap.** D137 and [stream-service.md](../plans/stream-service.md) call
  the per-axis remux *"architecturally free — LGPL, no encoder"*.
- **It is not.** A restartable, seekable HLS remux cut on a keyframe grid, with demuxed audio
  renditions, is most of D4's on-demand segmented machine without the encoder. D4 itself says it
  *"needs a spike against a real library"*.
- **A cheaper design covers more of Cut A** (§9, P2): **prepare.** One node job per title runs
  one FFmpeg command with these outputs:
  - video copied, or encoded to ~8 Mbps for remote viewing
  - AAC stereo with the dialogue-boost matrix, plus a plain track
  - text subtitles extracted
  - fMP4 HLS written as a growing `EVENT` playlist into the cache

  **Playback starts once the first segments exist.** A remux runs thousands of times faster
  than real time (2,163× measured, [testing-strategy.md](../plans/testing-strategy.md)).
- **That one mechanism is six Cut A features:**
  - remux
  - audio transcoding
  - the dialogue boost
  - the Cast container problem
  - subtitle extraction for that title
  - D175's prepared versions

  It is D4's third path, "background-prepared", with D169's *"the prepared rendition is a
  cache"*.
- **Live segment-addressed remux waits for a measurement.** It gets built only if first-play
  latency turns out to hurt.

### 1.3 Cut A needs a publicly trusted HTTPS name, and nothing plans one — **confirmed**

- **The microphone requires HTTPS.** `getUserMedia` works only in a secure context, so her
  phone's voice companion needs HTTPS.
- **So does her login from outside the house.** Credentials cannot cross the internet in the
  clear.
- **D25 knew about the certificate problem, but no Cut A plan owns it.**
  [remote-access.md](../plans/remote-access.md) says *"Depends on: —"* and has no certificate
  plan.
- **Correction to the architecture reviewer:** the Cast receiver itself is not blocked.
  Google's registration documentation says the receiver must be HTTPS once published, but *"the
  content loaded on the Web Receiver app may be served over HTTP"*.

**Resolution proposed** (P5):
- one name for the owner's server, with a certificate from ACME DNS-01
- the same name on the LAN and the WAN, through split-horizon DNS or hairpin NAT
- worked out first, as part of the reachability step

### 1.4 Watch Together is designed for an accountless guest; Cut A's guest has an account — **confirmed**

- **The plan's guest has no account.** In [watch-together.md](../plans/watch-together.md), a
  link guest *"is not a principal … no play state"* (D117, D125).
- **Cut A's guest does.** D174 and D178 give the remote person an invited account.
- **So the question that matters for Cut A is unanswered:** whose play state advances when the
  two of them watch together?
- **The link machinery serves the wrong case.** Rotation, the participant cap, ejection and
  refused-join signals were built for a case Cut A doesn't have. On the case it does have, they
  record her viewing as the host's.

**Resolution proposed** (P6):
- Cut A sessions admit signed-in users only, and each person's play state records as their own.
- Her TV joins by device-code pairing (D93).
- The anonymous link and everything around it wait for a guest who has no account.

### 1.5 The transcoder has three homes

- **Three places claim it:**
  - a tier-3 plugin on the public API (D19; ROADMAP Phase 4, *"build the interface last"*)
  - a node capability ([media-nodes.md](../media-nodes.md))
  - a `transcode` role (media-nodes.md)
- **Cut A needs an encoder now,** for prepared versions (D175).
- **Resolution proposed** (P3):
  - The encoder is a node capability. A node advertises `remux`, `aac` and `h264_qsv`, and a
    remote GPU node later is D19's promise with no plugin API at all.
  - Tier 3 dissolves into the node. D19's argument (rffmpeg, the machine that encodes need not
    be the one that serves) was written before the node model existed, and the node model
    already satisfies it.

### 1.6 Four cheap facts decide between designs, and none has been measured

1. **Phase 0.** What fraction of the owner's library direct-plays in Chrome, Safari and a
   Chromecast.
   - [playback-survey.md](../plans/playback-survey.md) was never narrowed to those three, as
     D178 §4 asked.
   - **The lab owns no Chromecast** (D190), so Phase 0 cannot run as re-scoped without buying
     one.
2. **The owner's line:** whether it is behind carrier-grade NAT, and whether it has IPv6.
3. **Her television:** which browser it has and what it supports for Cast (already asked, due
   in about two weeks).
4. **Remux and extraction throughput from the NAS over its real link.**
   - D114's rates come from one 10-minute file on one machine and are CPU-bound.
   - Extraction and remux read the whole file, so on a gigabit link a 10 GB film takes about
     90 s, not *"~2 s"*.
   - "Subtitles at scan time for the whole library" is therefore days of disk reads, not
     minutes.
   - This is the owner's own rule: measure the realistic bound.

### 1.7 Smaller architectural gaps

- **Database write concurrency is unstated.** Scan ingest, play spans and the fetch queue all
  write. Needed: one writer goroutine with batched transactions, or a pool with `busy_timeout`.
- **There is no job queue.** The overview's `jobs/` is *"a typed, persisted, inspectable
  queue"* with no plan and no table; `fetch_queue` is the only queue in `schema.md`. Prepare,
  fetches and scans need cancellation, a concurrency limit per device (one encode on an N95)
  and restart after a crash.
- **There is no error model.** Needed: one JSON error shape with a stable `code`, shared with
  the SDK as one enumeration. The transcode-reason field and remote-access's failing-hop codes
  belong in it.

- WASM plugins
- Landlock and seccomp

**Cut A should spend three: D2, D26 (in the per-invocation form) and Watch Together.**

### 3.1 `schema.md` is valid SQL and needs four fixes before it becomes migration 0001

The reviewer loaded it into SQLite 3.46 and it runs.

1. **There is no `setting` table.**
   - D181 says whatever changes at runtime lives in the database, and D184 creates many visible
     defaults, but they have nowhere to live.
   - Examples: the TMDB key, each user's OpenSubtitles credentials (which
     `subtitle-acquisition.md` defers to `auth.md`, where nothing exists), play-state
     thresholds and backup retention.
2. **Authored choices sit in re-derivable tables.**
   - `title.source`, `title.source_id` and `ident='confirmed'` are the user's choices (D170,
     D172, D183), and so are the scanner view's "ignore" decisions.
   - All of them sit in class O/F tables, which the migration policy allows to be dropped and
     re-derived.
3. **`cache.db` is not a cache.**
   - Resolved columns re-derive from `provider_response`, which lives in `cache.db`, and
     `cache.db` *"may be deleted at any time"*.
   - Deleting it forces the refetch D170 forbids.
   - Fix: move `provider_response` to `library.db`, or declare the resolved columns
     authoritative.
4. **Node state has no home:**
   - the last journal sequence consumed per node
   - the "last complete scan of this root" that D179's tombstone rule depends on
   - the node status record
   - a node's enrolment credential

   If these live in memory, the schema should say so.

## 4. Facts that correct the tree

1. **D112 blamed the wrong layer. Corrected in place.**
   - **The errno names the cause:**
     - `EOPNOTSUPP` (95): built in but disabled at boot
     - `ENOSYS`: not built
     - `EPERM`: a seccomp filter denied the call
   - **Docker is not the cause.** Its default profile has allowed the three Landlock syscalls
     since Docker 23 (moby #43199; profile checked).
   - **The 95 this sandbox measured came from the Proxmox VE kernel.** Its `CONFIG_LSM` omits
     Landlock, and a Proxmox staff member declined to change that in January 2026.
   - **Debian's kernels enable it:** bookworm 6.1 and trixie 6.12.
   - **The owner's Proxmox hosts, and every LXC on them, have no Landlock** until the kernel
     command line gains `lsm=landlock,…`.
   - **Synology's kernels will always report `ENOSYS`.** DSM 7.2 runs 4.4 or 5.10, and Landlock
     needs 5.13.
   - D190's rule that the escape test must first see the open succeed still stands. The denial it
     rules out is the container's mounts or file permissions, not Docker's seccomp.
2. **Navidrome, D31's reference, uses the cgo `mattn` driver.** The connection string D31
   borrows is mattn syntax. The pure-Go drivers spell it `_pragma=busy_timeout(…)` and may
   silently ignore the other form. Pragmas must be read back at startup.
3. **ncruces/go-sqlite3 no longer runs on wazero.** It is now Wasm translated into Go ahead of
   time, so choosing it no longer pre-pays the plugin runtime.
4. **react-native-web has had no release since 2025-10-16.** The Extism Go SDK has had none since
   2025-03-02 (v1.7.1), although Extism's core and wazero are active.
5. **jellyfin-web does not use JASSUB.** It pins `@jellyfin/libass-wasm`. JASSUB is active
   (2.5.16, 2026-09-05) but has one principal maintainer.
6. **Cut A needs a video encoder.** Prepared ~8 Mbps versions need x264 or a hardware encoder,
   so the LGPL-only packaging argument does not hold for Cut A. It is harmless, because the
   server is GPLv3.
7. **Two licence questions for later:**
   - libmpv is GPL unless built with `-Dgpl=false`, which matters for an App Store client
     under D80.
   - Google's Cast receiver SDK is a proprietary script loaded at runtime. D16's "no nonfree
     components" should exempt it by name, as it already implicitly exempts the platform.

## 5. Technology choices

| Choice | Verdict | Why |
| --- | --- | --- |
| Go server, one binary with modes (D9, D43) | **Keep** | Many subprocesses, long-lived streams, a static cross-compiled binary, fast build loops. The compiler catches most agent mistakes. |
| SQLite in WAL mode (D31) | **Keep** | The measurements hold; backup is `VACUUM INTO`. |
| Pure-Go driver: modernc (v1.59.0) or ncruces (v0.35.5) | **Keep, with guardrails** | Both are active and both have one maintainer. Keep the driver behind one `Open()`. Read back `journal_mode`, `busy_timeout`, `foreign_keys` and `synchronous` at startup and refuse to run if they are wrong. Don't let the benchmark between the two block Cut A. |
| sqlc (D6) | **Keep, fenced** | It turns a wrong column name into a build error. SQLite is its weakest engine: FTS5 and inferred types. Use it for the static queries, and fail CI on `interface{}` in generated code. |
| **Dynamic SQL** | **Pick one mechanism** | D6 allows a hand-written builder *or* squirrel, and D164 adds the predicate compiler, which makes three ways to do one thing. Cut A: one small hand-written filter builder for search; the predicate compiler replaces it when rules arrive; squirrel is banned. |
| Custom migration runner (D181) | **Keep** | A few hundred lines, well within agent ability. |
| FFmpeg as a subprocess (D26) | **Keep the boundary, re-rank the confinement** | See below. |
| FFmpeg build | **Cut A: pinned jellyfin-ffmpeg portable, bundled, hash-checked at startup** | Cut A needs an encoder and QSV (§4.6). Its hardware-acceleration patches are tested on the same NAS hardware. Our own trimmed LGPL build (a fork of BtbN's MIT scripts: no network, only the census's decoders) is a public-release question. Never point at BtbN's download URLs, which keep 14 daily builds. Never download FFmpeg at runtime. |
| WASM plugins (D12) | **Defer past Cut A** | §2. When they come, the choice is Extism if its Go SDK has revived, otherwise wazero with a JSON-in/JSON-out ABI of our own, which is easier for an agent to get right. |
| REST + OpenAPI from code (D20, D85) | **Keep, and name the tools** | **huma v2** (code-first, OpenAPI 3.1), never swaggo annotations. TypeScript: `openapi-typescript` plus `openapi-fetch`. The D85 gate: `oasdiff`. |
| HLS with CMAF/fMP4 (D3); hls.js | **Keep** | hls.js 1.7.3 is active. On Cast the receiver's own player handles HLS, so fMP4 HLS must be tested on a real Chromecast in Phase 0. |
| JASSUB | **Keep, pinned** | It has a bus factor of one. The fallbacks are Jellyfin's libass-wasm and D78's overlay. |
| **Web client inside the React Native shell (D10)** | **Change: plain React + TypeScript + Vite** | Cut A is a browser, a phone browser and a Chromecast. The player, subtitles, the Cast sender, WebRTC and screen readers are all DOM work that react-native-web abstracts badly, and react-native-web has been dormant for eleven months. React DOM is also where agents' training data is densest. The SDK stays free of React (D28 rule 2), so nothing is lost. |
| **React Native for the TV client (D10)** | **Decide at the TV client, with a paired prototype** | react-native-tvos is healthy (0.87.1-1), but the case for React Native has weakened. Phones are the web client (D176). Her TV may be served by the cast receiver. Compose for TV (`tv-material` 1.1.0) with Media3 is one language and one build system, and its errors surface at compile time, where agents fix them well. A React Native native module fails at run time, on a device. **Build the same four screens in both, time-boxed, when TV work starts.** One real pull the other way: Amazon's Vega OS sticks take React Native apps, or a web build (app-stores.md). Nothing React Native-shaped should be built before that. |
| Native player modules, libmpv | **Defer with the TV client** | No maintained general React Native libmpv module exists. The libmpv licence question is in §4.7. |
| react-i18next (D51) | **Keep** | Works the same in plain React. |
| Voice (D63, D68) | **Keep the design; build it as browser WebRTC plus embedded `pion/turn`** | Signalling on the session WebSocket. TURN on UDP, plus TCP/TLS on 443 for hostile networks. No SFU and no LiveKit, which would be a second service. |
| Cast receiver as a web app (D124) | **Keep** | A second Vite entry sharing the SDK and player packages. |
| Licence split (D80) | **Keep** | Every server dependency checked is GPLv3-compatible. |

**FFmpeg confinement, re-ranked so the default describes what most users actually get:**

0. **Argument hardening, everywhere and free.** `-protocol_whitelist file,pipe`, an explicit
   input format where known, and no `concat` or `hls` demuxers on untrusted input. This closes
   FFmpeg's best-known file-read and server-side request forgery class without any kernel
   feature.
1. **Mounts.** Media read-only, the cache the only writable path, and a non-root user.
2. **A seccomp denylist, not an allowlist.** Deny inet sockets for probe and extract, plus
   `ptrace`, `mount`, `bpf`, `keyctl`, `unshare` and `setns`.
   - A denylist cannot break FFmpeg on a hardware-acceleration path we never tested.
   - An allowlist will, as a `SIGSYS` crash the user sees as "playback broken".
   - Tighten toward an allowlist only after the device lab has recorded real syscall sets. An
     allowlist of BPF syscalls is also the weakest ground for agents: numbers differ by
     architecture and libc, and failures are far from the code.
3. **Landlock where the kernel has it,** best-effort, per invocation, with the errno reported as
   a cause and a remedy (§4.1).
4. **macOS and Windows development builds compile confinement to a no-op that reports
   "unconfined".** The escape test runs on Linux CI and in the lab.

## 6. Packaging, installation, maintenance

**Where the support burden lives,** measured from issue-form fields:

| Project | Share of reports from containers |
| --- | --- |
| Navidrome | 71% |
| Audiobookshelf | 82% |
| Jellyfin | ~60% |

Plex's broader forum is different: 37% Windows and 23% NAS vendor packages. Home Assistant
dropped two install methods used by under 6% of installs because they carried *"a
disproportionate burden"*. **Every channel we call supported must be tested in CI; everything
else is "community".**

**What users complain about, in order:**
1. **Upgrades that break the database.** Jellyfin 10.11's migration failures (#15027, 121
   comments), Immich's *"Breaking changes every week!"*, and Watchtower pulling a new major
   version.
2. **Permissions and PUID/PGID.**
3. **Getting the GPU into a container.** Users look up render-group IDs by hand.
4. **Mismatched FFmpeg builds.** Synology's Jellyfin package ships a generic FFmpeg.
5. **Rollback as an afterthought.** Caddy deletes the old binary on success, and Jellyfin
   deleted its pre-migration backup.

**Recommended channels:**

- **Cut A:**
  - a `.deb` built with nfpm, containing D44's systemd units, installed on a machine whose
    kernel has Landlock, plus the same `.deb` on a VPS if a tunnel is needed;
  - tarballs and an OCI image from the same pipeline, with the image run in CI;
  - no Windows, no macOS server, no NAS store.
- **First public release:**
  1. The OCI image, tagged `X`, `X.Y` and `X.Y.Z`, with **no `latest` that crosses a major
     version**.
  2. A signed apt/rpm repository.
  3. Tarballs with `mediaserver service install`.
  4. NAS stores through other people's catalogues (TrueNAS, Unraid, Umbrel), seeded by us.
  5. **No Synology package.** It has no Landlock, the packaging burden is heavy, and it would
     mean a second FFmpeg that users break. Synology users get the Container Manager route, with
     the confinement report saying *unconfined* out loud.
- **Updates:**
  - The package manager or the image tag owns updates. The binary never replaces itself in the
    background.
  - Checking for updates is asked at setup (D183) and reads a minisign-signed feed, verified
    against a key compiled into the binary.
  - `mediaserver upgrade`, for tarball installs only, keeps the previous binary.
  - Rollback is D181's snapshot plus the old binary, and the refusal message names both.
- **The Cast receiver** is one static HTTPS page on a project domain, serving every server
  version by versioned bundles. For Cut A, keep it unpublished and register her device by serial
  number (about 15 minutes and a reboot).
- **Android:** two flavours, like Jellyfin's:
  - `libre`: no Play Services, for F-Droid;
  - `full`: with Cast.

  For Cut A, the APK is a GitHub release, also served by the user's own server with old
  versions kept (D108). Register the package name and key under Google's developer verification
  before any public release (app-stores.md).

**Keeping it simple:**
- **Setup:**
  - One install command. The only required input is where the media is.
  - A **one-time setup code** in the log gates the first-run wizard, so nobody else on the LAN
    can claim the admin account.
- **Directory layout:** state under `/var/lib/mediaserver` (**backing it up is the whole
  backup**) and regenerable data under `/var/cache/mediaserver`. The config file holds only what
  must exist before the database opens (D182).
- **Container user:** the image runs as a fixed non-root UID from its first instruction, with no
  `chown` and no `su-exec`, and honours Docker's own `user:`.
- **Diagnosis:**
  - `/health` reports `starting | migrating | ready | degraded(reasons)`, and a migration counts
    as healthy (the Jellyfin #12035 lesson).
  - **`mediaserver doctor`** checks writability, the FFmpeg hash, confinement with errno and
    remedy, media readability as our UID, the GPU group, backup age and `quick_check`. For any
    failure it prints the exact line to add.
- **Release pipeline:** goreleaser with `CGO_ENABLED=0 -trimpath`, the web client embedded with
  `go:embed`, SBOM, cosign and minisign. A second runner rebuilds and diffs the binary, because
  the reproducibility claim needs a check that can fail.

**Where Cut A runs is the owner's choice, with one fact attached:**
- **The Debian NAS (devnas) should have Landlock and has Quick Sync.** On Apollo Lake that means
  H.264 encode and 8-bit HEVC encode.
- **The Proxmox hosts do not have Landlock** until their kernel command line is edited.
- **Run `cat /sys/kernel/security/lsm` on each machine first.**

## 7. Structuring the code so agents err less and are caught sooner

**The finding that shapes the rest:** yoloAI measured its own guidance.
- Its factual-accuracy principle *"fired zero times in six"*.
- Its 40-entry agent-failures log concludes: *"Execution catches my errors. Reading does not."*
- Anthropic's guidance agrees: CLAUDE.md is advisory, hooks are deterministic, and CLAUDE.md
  should stay under 200 lines.

So each rule goes at the leftmost level that can hold it: **type system → code generator →
lint → test → hook → prose**. Prose points at the mechanism rather than replacing it.

Ranked by payoff for cost, cheapest before the first commit:

1. **One `make check`, run by a Stop hook, from commit one.** Unlike yoloAI's hook, it also runs
   `check_docs.py` when docs change.
2. **Agents cannot edit the gates.** A pre-edit hook blocks changes to:
   - lint and tsconfig files, and the hooks themselves
   - generated code
   - applied migrations
   - frozen baselines
   - the dependency allowlist

   The block message says what to do instead. This is the cheapest defence against loosening a
   gate to make it pass (yoloAI A19; ImpossibleBench).
3. **The design's promises become lint rules and architecture tests before the packages exist.**
   depguard checks direct imports only, so each transitive claim also gets a `go/packages` test.
   - **Core never runs FFmpeg or parses media:**
     - depguard bars core from `os/exec`, image packages and `internal/node`;
     - forbidigo bars file reads in core outside `datadir`;
     - `TestArch_CoreNeverExecs` checks the transitive imports.
   - **Nothing deletes under a media root:**
     - media roots open through `os.Root` wrapped in a read-only type;
     - forbidigo bars `os.Remove`, `Rename` and `Truncate` outside the trash and sidecar
       packages;
     - a test hashes every fixture before and after a full scan.
   - **One way to do it:** a depguard deny-list of the alternatives (gorm, sqlx, squirrel,
     logrus, zap, testify/mock, viper, other routers). `time.Now`, `os.Getenv` and
     `exec.Command` are allowed only in their one wrapper each.
   - **Licence by directory:** SPDX headers must match their directory, and
     dependency-cruiser stops MPL code from importing GPL code.
   - **No device database:** the decision package takes a `Capabilities` value and cannot see
     the request. `User-Agent` reads are barred outside logging.
4. **Strict settings.**
   - **Go:** exhaustive switches with `default` *not* counting as exhaustive, so a new codec
     breaks every switch that doesn't name it. Also errcheck, nilerr, errorlint, and wrapcheck
     at boundary packages only. Every suppression must give a reason.
   - **TypeScript:** `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, and
     `strictTypeChecked`, with no `any`, no type assertions, and no floating promises.
   - **Frameworks:** no reflection-heavy DI, ORM or mock frameworks. Their errors surface at
     run time.
5. **Generated code** (sqlc, the OpenAPI document, the TypeScript client) is committed, never
   edited by hand, and regenerated and diffed in CI. Hand-written `fetch` calls to the server
   are banned by lint.
6. **Adding a dependency is an owner action.** It is enforced by an allowlist that carries a
   reason per entry, plus a hook on `go get`/`npm i`. Frontier models in 2026 still invent 4.6–6.1%
   of the package names they suggest.
7. **A guard that tests don't get weaker.** For each change it lists:
   - deleted tests
   - new skips
   - fewer assertions
   - widened tolerances
   - changed goldens

   Any of these needs a trailer. This sits beside D190's revert-and-require-red, with a lint for
   code that only its own test calls.
8. **Each package gets a short `doc.go`** with its purpose, its invariants (each naming its test
   or lint rule), the 3–7 decisions to read before changing it, and where to change things.
   **This is how 360k words become usable: by path, not by search.** When code lands, the plan
   section it implements gets an `IMPLEMENTED — see <package>` banner.
9. **Layout:** one monorepo and one Go module, with directories that follow the trust and
   licence boundaries:
   - `internal/core`, `internal/node`, `internal/nodeproto` (wire types, no logic), `internal/store`
   - `web/` with `packages/sdk`, `apps/web` and `apps/cast-receiver`

   No `util` or `common` packages. Files warn at 400 lines and fail at 800, because a file that
   fits in one read gets read whole.
10. **Guidance files:**
    - `AGENTS.md` of at most 150 lines, rules not reasons, imported by `CLAUDE.md`;
    - path-scoped `.claude/rules/` that load only when those paths are touched;
    - an advisory reviewer subagent with a fixed checklist: is the code reachable, were errors
      swallowed, is a helper duplicated, is there a new idiom;
    - `agent-failures.md` from day one, with a "Caught by" field.
