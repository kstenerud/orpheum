# M3's closing audit (2026-09-29)

The fifth audit between milestones, and the second of M3. [The first](audit-2026-09-27.md) found
M3 built but not done and asked for five rounds of work: contract renames (D227), internal
renames, duplicates, derived data and stale documents, and a migration squash (D228) came with
them. This audit runs the whole [checklist](../../audit-checklist.md) over what those 136 commits
(an earlier commit..78bb2ea`) changed, and over the whole tree for derived data, duplicates and calls to
other hosts. It ran as five parallel read-only reviews; each finding was checked at its use sites
before it was fixed or put to the owner. Fixes needing no one's decision were made the same day
and are listed with their commits; the rest are §9's proposals.

## 0. The verdict

M3's features are built, and the three things the last audit found unbuilt are built: the node's
eviction of prepared renditions (D217 §5), hardware encoders, and the Playwright timing test. What
stands between M3 and done is on devices: iPhone Safari (VQ14), `mediastreamvalidator` on the
owner's Mac (VQ15) and the escape test on devnas (VQ9). The reviews found five behaviour bugs no
test had seen, one of which (the "Disk gone" button, §9 A1) needs a contract change. The branch
gates checked far less than they reported in this sandbox (§6): the default base was five days
stale, and one trailer anywhere in a range excused every weakening in it.

## 6. The process (items 12–15)

**Gates that passed wrong work:**

- `check-pr`'s default base, `origin/main`, is 323 commits behind in this sandbox: revert-red saw
  285 of 314 files as added (a revert is then a build failure, not a test), and test-weakening
  skips added files, so a run without `BASE=` checked almost nothing (P37).
- A `Test-Weakened:` or `Gate-Changed:` trailer on any commit in the range excuses every weakening
  or gate edit in it.
- Python tests are invisible to test-weakening; revert-red silently skips CSS, migrations and
  config (a `fix` that changed only a stylesheet could never go red); revert-red's probes ran
  beside the timing tests, so load could turn a probe falsely red.
- The kept probe worktrees tested a stale tree after their first run (fixed, an earlier commit; its
  window held two behaviour commits, rechecked).
- A fake core in the node agent's tests reported after its test ended and panicked the package
  (fixed); no other fake server in the tests is exposed.
- Nothing installs Playwright's browsers: CI's browser tier would fail.

**Gates that fought correct work:** test-weakening counts a renamed test as removed (54 flagged in
the range, 41 of them renames); a refactor inside a `fix` commit is flagged by revert-red until the
base moves.

**Agent failures:** each of A1–A13 keeps its gate. A12 (old names left live) recurred three times
after its own fix, found each time by an audit and never by a gate. A decision's Status said
"built" in the commit that recorded it, before any code (D226, D227, D228): P31 again.

**Verification queue:** VQ1, VQ7, VQ9, VQ10, VQ11 and VQ13 are unticked; VQ14 and VQ15 are new.
VQ7's flow across two browsers and VQ4's second device could be Playwright tests with two
contexts.

## 9. What the owner is asked to decide

never told which mounts are missing; recommend the root's body lists its missing mount paths. A2:
a viewer refused for a full disk sees only "could not be prepared"; recommend a reason for the
viewer. A3: build D223 §8's carry to a file that gains the matching track. A4: one host breaker
for fetches and images, and requeue first matches that failed because the host failed. A5: store
why an image or a loudness measurement was refused, and retry when that cause changes. A6: add the
inode and ctime to the node's hash memo. A7: retry a download link while it is valid, and keep a
fetched subtitle only once the node has converted it (D224 §5).
